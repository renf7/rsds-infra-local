# Agent instructions

Before running local validation, follow README.md sections "Reproduce the successful local run" and "Troubleshooting without losing evidence". They document the tested Docker/cgroup workaround, context selection for builds, isolated workdirs/ports, stale-binary handling, evidence requirements and owned-state cleanup. Keep the human/agent runbook current when changing those behaviors.

This Go repository is part of renf7's rsds-infra family. Read the canonical standard at https://github.com/renf7/rsds-infra-helm/blob/main/docs/security/REPOSITORY-STANDARD.md (until merged, Helm PR #4 / branch RSDSINFRA-24-security-scanning).

Keep free CodeQL Go/Actions, Semgrep CE, Trivy, dependency checks, SonarCloud quality gate, Dependabot and secret protection requirements. Trigger applicable checks on every PR commit/force-push and opened/reopened/edited/ready_for_review event. No paid tiers, token leaks, blanket exclusions or weakened gates. This repository will remain Go and tooling only: omit Java and React scanners, including SpotBugs/Find Security Bugs and React ESLint plugins. Maintain locked versions and SHA-pinned Actions. Read SCANNER-VERSIONS.md for applicability and verified native settings.

Never use a global Kubernetes context or production credentials for local tests. Require a local Docker endpoint and a dedicated rsds-local-* cluster/private kubeconfig. Cleanup only owned state; never Docker-prune or delete arbitrary paths/clusters. Preserve exact default-branch/PR source provenance, fail on mismatched served content, and do not claim missing backend coverage. Add each future backend to the manifest only when its repository and Helm values exist. Keep Jira RSDSINFRA-25 and epic RSDSINFRA-8 current.

Browser E2E is disabled by default. Run the Docker-contained headless Chromium suite only when up receives the explicit --e2e flag; otherwise avoid browser image builds/downloads and record e2eEnabled=false. CI must explicitly opt in for both source-selection modes. When enabled, E2E failures must block PASS. Keep browser/package versions matched, report validation fail-closed, tests deterministic and runtime/network errors visible. Maintain CodeQL Python coverage and Dependabot pip/Docker entries for E2E tooling; no React or Java scanners. Preserve screenshots, JUnit, JSON and traces without kubeconfigs. Track this behavior in RSDSINFRA-26.

For authentication integration use README's optional full authentication stack instructions. Keep the provider fixture strictly local, identify it in reports, build all three deliverable images from recorded source commits, and require all 36 tests in that mode. Preserve the 16-test frontend-only mode. Generated signing/Apple private keys belong only to the auth backend; fixtures receive public Apple client trust only. No authentication traces or credential-bearing artifacts. Production provider acceptance remains pending real registrations.
